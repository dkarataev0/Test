# Vibe Ideas — поиск идей для вайбкодинга

Цель — выдать пользователю **немного, но сильных** идей, которые: (1) решают реальную боль, (2) реально собрать с ИИ за ограниченное время, (3) подходят под его навыки и цели. Не список из 50 банальностей вроде «todo-приложение» и «трекер привычек».

## Шаг 1. Уточни рамки (быстро)

Если пользователь не указал — задай максимум 3 коротких вопроса или выбери разумные значения по умолчанию и явно их назови:

| Параметр | Варианты | По умолчанию |
|---|---|---|
| Цель | заработок / портфолио / для себя / обучение / фан | для себя + портфолио |
| Бюджет времени | вечер (2–4 ч) / выходные / неделя / месяц | выходные |
| Платформа | веб, Telegram-бот, расширение браузера, CLI, мобилка, десктоп, игра | веб |
| Навыки и стек | что уже знает, какие сервисы доступны (Supabase, Vercel, Netlify, Claude API…) | веб-стек + Claude API |
| Ниша / интересы | хобби, профессия, сообщество, где пользователь «свой» | — |
| Язык / рынок | RU / EN / глобальный | по языку запроса |

Лучшие идеи рождаются на пересечении **ниши, которую пользователь знает изнутри**, и боли, которую он видел сам. Всегда спроси (или предложи подумать): «что тебя раздражает в работе/хобби каждую неделю?»

## Шаг 2. Собери сигналы спроса

Если доступен WebSearch/WebFetch — ищи реальные боли, а не придумывай из головы. Готовые поисковые запросы и источники — в `references/sources.md`. Минимум:

1. **Жалобы и «хотелки»**: Reddit (`"is there an app that"`, `"I wish there was"`, `"I'd pay for"`), Hacker News (Ask HN), профильные Telegram-чаты, форумы.
2. **Существующие решения и их слабые места**: Product Hunt, отзывы 1–3★ в App Store / Google Play / Chrome Web Store, G2/Capterra, GitHub issues с большим числом 👍.
3. **Тренды**: новые API и модели, свежие релизы платформ (на них ещё мало инструментов), Google Trends, Exploding Topics.

Фиксируй каждую находку как сигнал: *кто страдает → что именно болит → как решают сейчас → ссылка*. Без интернета — используй `references/patterns.md` (паттерны и затравки идей) и честно помечай, что спрос не проверен.

## Шаг 3. Сгенерируй и отфильтруй

Сгенерируй 10–15 кандидатов, применяя паттерны из `references/patterns.md` к найденным болям. Затем **отсей** всё, что:

- требует сложного бэкенда, своих ML-моделей, железа, лицензий, работы с деньгами/медданными без готовых провайдеров;
- упирается в закрытые API или скрейпинг, нарушающий ToS;
- без сетевого эффекта бесполезно (соцсеть, маркетплейс с нуля);
- уже идеально решено бесплатным популярным инструментом (если нет явного угла: ниша, язык, цена, простота);
- не влезает в бюджет времени даже в урезанном MVP.

## Шаг 4. Оцени (скоринг)

Оцени оставшиеся по шкале 1–5:

| Критерий | Что значит 5 |
|---|---|
| **Боль** | люди сами пишут, что страдают / заплатили бы |
| **Вайбкодабельность** | стандартный стек, понятные API, ИИ уверенно напишет большую часть |
| **Время до MVP** | укладывается в бюджет с запасом |
| **Отличие** | есть ясный угол против существующих решений |
| **Дистрибуция** | понятно, где взять первых 10 пользователей (сообщество, сабреддит, чат) |
| **Вау / фан** | приятно делать и показать |

Итог = сумма; для цели «заработок» удваивай Боль и Дистрибуцию, для «обучения» — добавь критерий «чему научусь». Оставь **топ-3–5**.

## Шаг 5. Выдай идеи в формате карточек

Для каждой идеи:

```
### <Название> — <одна строка: что делает и для кого>
**Боль:** кто и что страдает (+ ссылка на сигнал, если есть)
**Угол:** чем лучше/иначе существующих решений
**MVP за <время>:** 3–5 фич, не больше
**Стек:** конкретные технологии и сервисы
**Первые пользователи:** где их найти
**Риски:** главное, что может не взлететь
**Скоринг:** Боль 4 · Вайб 5 · Время 4 · Отличие 3 · Дистрибуция 4 · Фан 5 = 25
**Первый промпт:** готовый промпт для старта вайбкодинга (1–3 предложения)
```

В конце — **рекомендация**: какую одну идею брать первой и почему. Предложи сразу начать: набросать структуру проекта, сделать прототип или проверить спрос (лендинг + пост в сообществе).

## Принципы

- Конкретика вместо абстракций: не «приложение для фитнеса», а «Telegram-бот, который по фото тарелки в столовой считает БЖУ и пишет итог дня».
- Узкая ниша лучше широкой: «для репетиторов по математике» > «для преподавателей».
- Скучные B2B-задачи (отчёты, конвертация, напоминания, парсинг документов) часто ценнее «крутых» B2C-идей.
- ИИ — средство, а не идея: «обёртка над ChatGPT» без данных, процесса или ниши — слабая идея.
- Не выдумывай сигналы спроса и ссылки. Если не проверял — так и скажи.
