# Интервью требований

Цель - получить тот результат, который пользователь хочет увидеть, а не тот, который пришлось угадать. Сначала вопросы и согласованное ТЗ, потом код.

## Когда пропускать

- Запрос уже однозначный (есть URL, поля, формат вывода, внешний вид) - сразу к работе.
- Мелкая правка (переименовать, поправить баг с понятной причиной).
- Ответ можно найти самому в коде репозитория - найди, не спрашивай.

## Процесс

### 1. Осмотрись (без вопросов)
Прочитай README, существующий код, CLAUDE.md. Не спрашивай то, что видно из репозитория (язык, стек, структура).

### 2. Задай вопросы инструментом `AskUserQuestion`
- За один вызов - до 4 вопросов, у каждого 2-4 варианта ответа. Пользователь всегда может выбрать «Другое» и написать своё.
- Рекомендуемый вариант ставь первым и помечай «(Рекомендуется)».
- Варианты - конкретные и понятные не-программисту: «Таблица Excel», а не «xlsx через openpyxl».
- Где удобно, добавляй `preview` - пример вывода, макет экрана, кусок таблицы. Это лучше всего показывает, «как будет выглядеть».
- `multiSelect: true` - когда можно выбрать несколько (например, поля для сбора).
- Обычно хватает 1-2 раундов. Не больше 3. Не задавай вопрос, ответ на который не меняет то, что ты сделаешь.

### 3. Чек-лист тем (выбирай только непокрытое)

**Для парсера:**
1. Источник: какой сайт/URL, нужна ли авторизация, сколько страниц/товаров примерно.
2. Данные: какие поля собирать (название, цена, ссылка, фото, описание, рейтинг…).
3. Результат: Excel / CSV / JSON / Google Sheets / база данных / Telegram.
4. Интерфейс: только командная строка, красивая консоль с прогрессом, веб-страница с кнопкой «Запустить», Telegram-бот.
5. Запуск: один раз, по расписанию, по кнопке.
6. Особенности: сайт на JavaScript, капча, пагинация, фильтры, язык/регион.

**Для любого интерфейса:**
- Стиль (минимализм, тёмная тема, яркий, корпоративный), примеры сайтов, которые нравятся.
- На каких устройствах будут смотреть (телефон / компьютер).

**Общее:**
- Что считается «готово» - как пользователь проверит, что всё работает.
- Ограничения: сроки, бюджет на платные сервисы, где будет запускаться.

### 4. Зафиксируй ТЗ и получи подтверждение
Коротко (5-10 строк) перескажи договорённость:

```
Что делаю: парсер каталога example.com/catalog
Собираю: название, цена, ссылка, наличие
Объём: ~500 товаров, все страницы пагинации
Результат: products.xlsx + красивый прогресс в консоли
Запуск: python -m parser
Готово, когда: файл открывается, в нём все товары без пустых цен
```

Если в ответах осталось противоречие или важная неизвестность - один уточняющий вопрос. Иначе начинай работу и сообщи, какие разумные допущения ты сделал.

### 5. Во время работы
- Новый развилочный вопрос (например, сайт оказался за капчей) - снова `AskUserQuestion` с вариантами решения, а не тихий выбор.
- По завершении сверь результат с пунктом «Готово, когда» и покажи пример реального вывода.
