# Parser Builder — парсер, который работает

Если требования неясны (сайт, поля, формат результата, интерфейс) — сначала скилл `requirements-interview`. Для внешнего вида (консоль, веб-интерфейс, отчёт) — скилл `parser-ui`.

## Порядок работы

1. **Разведка сайта, до кода.**
   - Скачай страницу (`curl -sL -A "<браузерный UA>" URL -o page.html`) и посмотри, есть ли нужные данные в HTML.
   - Ищи скрытый API: `<script type="application/ld+json">`, `__NEXT_DATA__`, `window.__INITIAL_STATE__`, XHR-запросы к `/api/`. JSON-API надёжнее и быстрее HTML — используй его, если есть.
   - Данных нет в HTML и API не найден → Playwright (см. ниже).
   - Проверь `robots.txt` и условия сайта; не обходи авторизацию и капчу без явного разрешения пользователя — спроси.
2. **Сохрани образцы** 1–2 страниц в `tests/fixtures/` — на них пишутся тесты селекторов.
3. **Напиши парсер по структуре ниже.**
4. **Прогони на реальном сайте** на маленьком объёме (`--limit 5`), затем полностью. Покажи пользователю пример результата.

## Стек по умолчанию

| Задача | Библиотека |
|---|---|
| HTTP | `httpx` (sync или async, HTTP/2, таймауты) |
| Разбор HTML | `selectolax` (быстро) или `beautifulsoup4` + `lxml` |
| JS-сайты | `playwright` (Chromium уже установлен в окружении — не запускай `playwright install`) |
| Повторы | `tenacity` |
| Модель данных | `pydantic` v2 |
| Экспорт | `openpyxl` / `pandas` для Excel, `csv`, `json` |
| CLI и красота | `typer` + `rich` (см. `parser-ui`) |
| Тесты | `pytest` |

## Структура проекта

```
parser/
  __main__.py      # точка входа: python -m parser
  config.py        # настройки: URL, задержки, лимиты, пути (pydantic-settings / .env)
  client.py        # HTTP-клиент: заголовки, таймауты, ретраи, rate limit
  scraper.py       # обход: список страниц → карточки, пагинация
  parse.py         # чистые функции html -> модели (тестируются на фикстурах)
  models.py        # pydantic-модели записей
  export.py        # сохранение в xlsx/csv/json
tests/
  fixtures/*.html
  test_parse.py
requirements.txt
README.md          # как установить и запустить, пример вывода
```

Разделяй **загрузку** и **разбор**: `parse.py` не делает сетевых запросов, принимает строку HTML и возвращает модели. Так его легко тестировать и чинить, когда сайт меняет вёрстку.

## Обязательные правила надёжности

Подробности и шаблоны кода — `references/patterns.md`.

- **Таймауты** на каждый запрос (connect ~10 с, read ~30 с).
- **Ретраи** с экспоненциальной задержкой для 429/5xx/сетевых ошибок; 404 — не повторять. Учитывай `Retry-After`.
- **Вежливость**: задержка между запросами (0.5–2 с, со случайным разбросом), ограничение параллельности (2–5), реалистичный `User-Agent` и `Accept-Language`.
- **Одна сессия** клиента на весь прогон (переиспользование соединений, cookies).
- **Устойчивые селекторы**: `data-*` атрибуты, `itemprop`, семантические теги — а не `div:nth-child(3) > .css-1x2y3z`.
- **Нормализация**: цены → `Decimal`/`float` без пробелов и валюты, относительные ссылки → `urljoin`, пробелы `strip()`, даты → ISO.
- **Пустое поле ≠ падение**: если поле не найдено — `None` + предупреждение в лог; одна битая карточка не роняет весь прогон.
- **Дедупликация** по URL/ID.
- **Прогресс сохраняется**: промежуточная запись результата или чекпоинт, чтобы при сбое не начинать сначала (`--resume`).
- **Логи** в файл (`logs/parser.log`) + краткая сводка в конце: собрано N, пропущено M, ошибок K, время.
- **Ограничение** `--limit N` и `--dry-run` для быстрой проверки.
- Секреты (логины, токены, прокси) — только в `.env`, который в `.gitignore`.

## Проверка перед сдачей

- [ ] `pytest` зелёный (тесты `parse.py` на сохранённых фикстурах).
- [ ] Реальный прогон с `--limit 5` прошёл, данные осмысленные (нет пустых цен, ссылки абсолютные).
- [ ] Полный прогон (или достаточно большой) — сводка без массовых ошибок.
- [ ] Файл результата открывается; в Excel есть заголовки, нормальная ширина колонок, кликабельные ссылки.
- [ ] README: установка, запуск, пример вывода, известные ограничения.
- [ ] Показал пользователю итог: сколько собрано, где лежит файл, первые строки.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| 403 / пустая страница | Нет браузерных заголовков → добавить UA, Accept, Accept-Language; если защита от ботов (Cloudflare) — Playwright или спросить пользователя |
| Данные есть в браузере, но нет в HTML | Рендер на JS → искать JSON API в Network или Playwright |
| 429 Too Many Requests | Увеличить задержку, уменьшить параллельность, уважать Retry-After |
| Кракозябры | Неверная кодировка → `response.encoding` / `charset_normalizer` |
| Селектор вдруг ничего не находит | Сайт поменял вёрстку → обновить фикстуру, тест упадёт и покажет где |
| Бесконечная пагинация | Останавливаться, когда страница не дала новых элементов или нет ссылки «далее» |
